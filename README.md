# Token API 硬件成本测算工具

用于按模型结构、加速卡规格、单机或多机部署方式，以及 QPS 业务需求，估算 Aggregate Output TPS、月输出 Token、每百万输出 Token 的硬件成本和建议报价。

公开地址：<https://atlas13-yx.github.io/token-api-cost-calculator/>

## 快速使用

1. 选择模型预设，或手动填写模型名称、激活参数和总参数。
2. 选择权重精度，填写单卡 BF16/FP16 基准算力、量化内核实测倍率、卡数与显存。
3. 单机部署直接填写当前机器；多机部署需区分“一个完整副本使用的节点数”和“彼此独立的完整副本数”。
4. 容量模式用于估算可持续输出能力；QPS 模式用于按业务需求自动反算付费副本数。
5. 需要复用实测 TPS 时，补齐 TP/PP/EP、跨节点互联、带宽、RDMA、推理框架、版本、ISL/OSL 和并发后保存压测。

## 固定计算口径

```text
单副本 Decode 计算上限
= 单卡 BF16/FP16 TFLOPS × 量化内核实测倍率 × 单副本总卡数
  ÷ (2 × 每 Token 激活参数量)

无压测容量吞吐
= 单副本 Decode 上限 × 副本内并行效率 × 内核与服务效率

多副本总吞吐
= 单副本吞吐 × 独立完整副本数 × 副本间调度效率

月输出 Token
= 输出 TPS × 运行天数 × 日均有效负载小时 × 3600

硬件成本（元/百万输出 Token）
= 全部付费节点月租 ÷ 月输出 Token × 1,000,000
```

QPS 模式区分两个口径：

```text
可计费输出需求 = QPS × 平均输出 Token

无压测等效规划负载
= QPS × (平均输出 Token + 平均输入 Token × Prefill 等效负载系数)
```

等效规划负载只用于反算副本数，成本分母仍然只使用输出 Token。若存在严格匹配的 Aggregate Output TPS 压测，系统直接以该输出 TPS 规划，不再重复添加 Prefill 负载。

## 多机部署原则

- TP/PP/EP 跨多台机器是“一个完整模型副本的内部部署”，增加节点主要用于容纳模型与改变单副本吞吐，不等于增加独立模型副本。
- 只有能够独立接收和处理请求的完整模型副本，才会按副本数扩展总吞吐。
- 副本内并行效率描述跨卡、跨节点通信损耗；副本间调度效率描述多个独立副本之间的负载均衡损耗。
- QPS 模式会自动计算服务副本和冗余副本，并将全部付费节点计入成本。

## 严格压测匹配

压测仅在以下指纹全部一致时生效：模型、结构、激活参数、总参数、权重精度、硬件型号、基准算力、量化倍率、节点数、每节点卡数、TP/PP/EP、互联类型、互联带宽、RDMA 状态、推理框架、框架或镜像版本、ISL、OSL、并发及已设置的 P95 SLA。

旧版压测若缺少互联或运行时指纹，会继续保留在当前浏览器中，但不会被严格应用；补齐信息并重新保存即可。

## 可修改参数与固定规则

需要按实际环境填写或压测的参数包括：量化内核倍率、Prefill 等效负载系数、副本内并行效率、内核与服务效率、副本间调度效率、目标负载率、互联与运行时信息、实测 Aggregate Output TPS，以及可选的 TTFT/ITL。

固定规则包括：节点、卡数和副本数必须使用有效整数；每节点实际卡数不得超过整机标准卡数；权重必须能放入扣除显存预留后的单副本显存；无效配置不会被自动改写，也不会继续计算成本和报价。

## v2.0 更新摘要

- 无效数字输入改为明确拦截，不再自动改写成 1 张卡、1 个副本或 2 个节点。
- QPS 无压测规划新增 Prefill 等效负载，并保持输出 Token 为唯一计费产量。
- 页面明确拆分副本内部署与独立完整副本扩容。
- 副本数变化会同步更新付费节点、硬件成本和建议报价。
- 压测严格匹配新增互联类型、带宽、RDMA、TP/PP/EP 和运行时指纹。

## 使用边界

理论公式是 Decode FLOPS 容量上限，不等于真实服务吞吐；权重显存估算不包含精确 KV Cache、激活、通信缓冲和运行时内存。正式上线、SLA 承诺和对外定价应使用同硬件、拓扑、互联、运行时及工作负载下的实测数据，并叠加电力、网络、运维、许可和税费。
