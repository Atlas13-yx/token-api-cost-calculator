# Token API 硬件成本测算工具

用于按模型结构、加速卡规格、单机或多机部署方式，以及 QPS 业务需求，估算 Aggregate Output TPS、月输出 Token、每百万输出 Token 的硬件成本和建议报价。

公开地址：<https://atlas13-yx.github.io/token-api-cost-calculator/>

## 快速使用

1. 选择模型预设，或手动填写模型名称、激活参数和总参数。
2. 选择权重精度与硬件整机配置；使用 Ascend 910C 8 卡预设时硬件规格锁定，自定义整机时必须重新确认规格与月租。
3. 单机填写当前机器实际卡数；若超过单节点标准卡数，系统停止计费并提示切换多机。多机需分别填写“单副本拓扑节点数”“单副本实际总卡数”和付费硬件池。
4. 多机只需选择副本增加时硬件如何变化：默认“同步增加硬件”，也可使用固定节点池。只有部署或压测已确认整张空卡可以共用时，才在高级设置中填写每组实测可运行副本数。
5. 没有压测时选择“交互低并发、在线均衡或吞吐优先”；需要复用实测 TPS 时，单机补齐 TP/PP/EP、运行时、ISL/OSL 和并发，多机再补充互联、带宽与 RDMA 后保存实测。

## 固定计算口径

```text
单卡 Decode 理论上限（仅作参考）
= 单卡 BF16/FP16 TFLOPS × 量化内核实测倍率
  ÷ (2 × 每 Token 激活参数量)

无压测单副本吞吐
= 单卡 Decode 上限 × 各节点卡内 Amdahl 加速比之和
  × 跨节点通信效率 × 内核与服务效率

Amdahl 加速比
= 1 ÷ [不可并行比例 + (1 - 不可并行比例) ÷ 资源数量]

多副本总吞吐
= 单副本吞吐 × 完整副本数 × 多副本调度效率

月输出 Token
= 输出 TPS × 运行天数 × 日均有效负载小时 × 3600

固定节点池每组可运行副本数（自动）
= 向下取整(每组付费节点数 ÷ 单副本节点数)

高级实测空卡复用
= 手工回填同配置部署或压测确认的每组可运行副本数
且不得超过 向下取整(单组物理卡容量 ÷ 单副本实际总卡数)

固定池付费资源组数
= 向上取整(全部规划副本数 ÷ 每组可运行副本数)

硬件同步增加时的付费资源组数
= 全部规划副本数

整节点计费总月租
= 单节点月租 × 每组节点数 × 付费资源组数

按卡计费总月租
= 单卡月租 × 计费卡数

硬件成本（元/百万输出 Token）
= 集群总月租 ÷ 月输出 Token × 1,000,000
```

QPS 模式区分两个口径：

```text
可计费输出需求 = QPS × 平均输出 Token

无压测等效规划负载
= QPS × (平均输出 Token + 平均输入 Token × Prefill 等效负载系数)
```

等效规划负载只用于反算副本数，成本分母仍然只使用输出 Token。若存在严格匹配的 Aggregate Output TPS 压测，系统直接以该输出 TPS 规划，不再重复添加 Prefill 负载。

## 多机部署原则

- TP/PP/EP 跨多台机器是“一个完整模型副本的内部部署”；单副本实际总卡数会自动按节点容量装箱，例如 19 卡、3 个 8 卡节点显示为 8+8+3。
- 只有能够独立接收和处理请求的完整模型副本，才会按副本数扩展总吞吐。
- 节点内和跨节点都使用 Amdahl 非线性扩展；不可并行比例描述通信、同步和调度等无法随资源数量同时扩展的部分。
- 默认选择“同步增加硬件”：总节点数 = 单副本节点数 × 副本数，租金随副本数同步增加，最容易核对。
- 选择“固定节点池”时，每组可运行副本数 = 固定池节点数 ÷ 单副本节点数（向下取整），资源组数再按副本需求向上取整。
- 只有同模型、精度、拓扑和运行时的部署或压测已经验证整张空卡可共用时，才在高级设置中回填每组实测可运行副本数；该值不得超过物理整卡容量上限。
- 空卡是未分配给任何副本的整张卡；已分配卡上的剩余显存不能当作空卡。
- 多副本调度效率描述多个副本并发服务的损耗；严格匹配压测存在时，实测单副本 TPS 覆盖 Amdahl 估算。
- QPS 模式会自动计算服务副本和冗余副本；冗余副本增加成本，但不增加业务需求吞吐。

## 严格压测匹配

单机与多机都可保存实测 Aggregate Output TPS。实测仅在以下指纹一致时生效：模型、结构、激活参数、总参数、权重精度、硬件型号、基准算力、量化倍率、单副本节点数、单副本实际总卡数、单节点标准卡数、TP/PP/EP、推理框架、框架或镜像版本、ISL、OSL、并发及已设置的 P95 SLA；多机额外严格匹配互联类型、互联带宽和 RDMA 状态。付费硬件池大小不属于单副本压测指纹。

旧版压测若缺少互联或运行时指纹，会继续保留在当前浏览器中，但不会被严格应用；补齐信息并重新保存即可。

## 可修改参数与固定规则

需要按实际环境填写或压测的参数包括：自定义硬件规格与合同月租、量化内核倍率、节点内与跨节点不可并行比例、Prefill 等效负载系数、内核与服务效率、多副本调度效率、目标负载率、互联与运行时信息、实测 Aggregate Output TPS、经验证的每组可运行副本数，以及可选的 TTFT/ITL。

固定规则包括：节点、卡数和副本数必须使用有效整数；单机实际卡数不得超过所选整机规格；多机单副本实际总卡数不得超过其拓扑节点容量且每个节点至少分配一张卡；固定节点池每组节点数不得少于单副本节点数；自动容量按节点数计算；高级实测数量不得超过池内理论整卡容量；整节点计费按付费节点累计，固定池按卡计费按预留池卡数累计，同步增加硬件时按实际分配卡数累计；权重必须放入扣除预留后的单副本显存。无效配置不会被自动改写，也不会继续计算成本和报价。

## v2.0 更新摘要

- 无效数字输入改为明确拦截，不再自动改写成 1 张卡、1 个副本或 2 个节点。
- QPS 无压测规划新增 Prefill 等效负载，并保持输出 Token 为唯一计费产量。
- 页面明确拆分副本内部署与独立完整副本扩容。
- 副本数变化会同步更新付费节点、硬件成本和建议报价。
- 压测严格匹配新增互联类型、带宽、RDMA、TP/PP/EP 和运行时指纹。

## v2.1 计费模型更新

- 新增整节点计费与按实际卡数计费，结果区直接展示集群总月租和付费资源。
- 单机卡数变化通过节点内多卡效率影响吞吐；整机固定租金和按卡计费分别采用对应成本口径。
- 多机单副本改用“单节点基准 × 跨节点吞吐倍率”，节点增加不再自动线性放大有效吞吐。
- 节点、卡数或拓扑变化后，旧压测会严格失配；无压测时由用户按当前环境修改效率与倍率。

## v3.0 非线性扩展估算

- 无压测模式新增“交互低并发、在线均衡、吞吐优先”三个工程模板，默认使用在线均衡。
- 节点内多卡与跨节点扩展改用 Amdahl 公式，卡数和节点数增加不再自动按理想线性吞吐计算。
- 容量模式显示三类场景的敏感性结果；工程预设只是规划起点，不作为厂商性能承诺。
- 严格匹配的实测配置继续拥有最高优先级：单机采用整机 TPS，多机采用一个完整副本 TPS，匹配后直接覆盖工程估算。
- 压测管理升级为单机、多机共用：单机保存当前整机 TPS，多机保存一个完整副本 TPS。
- 租金仍严格按整节点或实际计费卡累计；资源变化和吞吐变化采用彼此独立的计算口径。

## v3.1 硬件池与副本占用

- 新增硬件整机预设：Ascend 910C 固定为 8 卡/节点；自定义整机不会静默沿用预设租金。
- 单机严格限制实际卡数不超过硬件规格，超限时停止计费、成本和报价，并提示所需最少节点数。
- 多机将单副本实际总卡数与付费硬件池拆分，支持 19 卡分布在 3 个 8 卡节点等非满配拓扑。
- 多机主界面合并为一个“副本增加时，硬件如何变化”选项；默认按副本同步增加硬件，固定节点池按节点容量分组，高级空卡共用只在实测后启用。
- 结果区同时显示付费节点、物理卡容量、副本分配卡数和空余卡数，避免把“使用卡”和“计费卡”混为一谈。

## 使用边界

理论公式是 Decode FLOPS 容量上限，不等于真实服务吞吐；权重显存估算不包含精确 KV Cache、激活、通信缓冲和运行时内存。正式上线、SLA 承诺和对外定价应使用同硬件、拓扑、互联、运行时及工作负载下的实测数据，并叠加电力、网络、运维、许可和税费。
